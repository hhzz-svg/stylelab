# 写作模块 v1：人工列章程 + 逐章生成

范围：给风格工坊补上「能写小说」的最小闭环。不接 ainovel-cli，不自动生成大纲，不一键写完全书。风格卡仍是技法来源；连续性靠「前几章摘要 + 上一章文末」。

未回复的选择按推荐落地：人工列章程、一次写一章、目标 2000–3500 字。

## 数据模型

在 `internal/store/migrate.go` 追加一张表（现有库用 `CREATE TABLE IF NOT EXISTS`，不加版本迁移）：

```
chapters
  id TEXT PK                    -- chp_ + 16 hex
  project_id TEXT → projects CASCADE
  card_id TEXT                  -- 写这一章时钉死的风格卡，无 FK
  card_version INTEGER
  seq INTEGER                   -- 1-based，同项目 UNIQUE(project_id, seq)
  title TEXT
  brief TEXT                    -- 章概括，人工写，≤200 字
  body TEXT                     -- 已生成或手改正文，空=未写
  summary TEXT                  -- 写完后自动生成、可手改；供下一章当前情
  status TEXT                   -- draft | writing | written | failed
  target_runes INTEGER
  model TEXT
  created_at / updated_at
```

一个作品一份手稿，不再套一层 manuscript。删作品时章节随 FK 一起删。

## API（沿用现有 202 job 约定）

全部走 `projects.user_id` 所有权 join，别人的资源一律 404。

- `GET /api/projects/{id}/chapters` → `{ chapters: ChapterSummary[] }`
- `POST /api/projects/{id}/chapters` `{ title, brief, card_id? }` → 201，seq 接到末尾
- `GET /api/chapters/{id}`
- `PATCH /api/chapters/{id}` `{ title?, brief?, body?, summary?, card_id?, target_runes? }` —— 手改正文/摘要
- `DELETE /api/chapters/{id}` → 204，后面的 seq 前移
- `POST /api/chapters/{id}/write` `{ model?, target_runes?, note? }` → 202 `{ job_id }`
- `GET /api/projects/{id}/manuscript.md` → 拼好的 Markdown 下载

`target_runes` 默认 2500，夹在 2000–3500。`brief` 必填且 ≤200 字。`note` 可选（≤200），只作用这一次生成。

## 写章任务

新包 `internal/write`，**不要复用** `internal/sample`（硬限制 800–2000、「短章试写器」）。

1. `job.KindWrite = "write"`，在 `cmd/stylelab/main.go` 注册。
2. 入队前把该章 `status=writing`；失败/取消改回 `failed`/`draft`。
3. 进度：`load` 10 → `llm_key` 20 → `generate` 55 → `summarize` 80 → `persist` 95 → `done` 100。
4. Prompt 上下文（`llm.ChapterSystem`）：
   - 风格卡 JSON（同试写：dimensions + prohibitions，不含 facts）
   - 全书已有章标题列表
   - 前 1–3 章的 `summary`（空则跳过）
   - 上一章正文末 300 字（衔接语气）
   - 本章 `title` + `brief` + 可选 `note`
5. 模型只输出正文。过 `ForbiddenCopyCheck`。
6. 第二次短调用生成 ≤120 字 `summary`（失败不挡正文，留空让用户手填）。
7. Job result：`{"chapter_id":"chp_…"}`。

## LLM 小改

`internal/llm/client.go`：

- HTTP 超时 120s → **180s**（整章生成）
- `Request` 增加可选 `MaxTokens`
- Anthropic 写章时 `max_tokens=8192`（现死 4096）；OpenAI / compatible 同样带上

试写/抽离/融合/审计不传 `MaxTokens`，行为不变。

## 前端

新路由：

- `/p/:id/write` —— 章程工作台（列章、加章、点写）
- `/p/:id/chapter/:chapterId` —— 单章：标题/概括/摘要/正文，可手改、可重写

侧栏在「融合」下加「写作」（新 icon）。Lab 工具栏加「写正章」→ `/p/:id/write?card={cardId}` 预选风格卡。

复用：`Crumb`、`page-head`、`Skeleton`、`registerJob` + `JobProgress` + `JobDock`。只需给 `JobResult` 加 `chapter_id`，`resultRoute` 指到章节页。

工作台交互：

- 顶部选默认风格卡（`listCards`）；新章继承，单章可改
- 列表：序号、标题、概括、字数、状态；空态引导先加一章
- 行内「写这一章」；已有正文再点走 `ConfirmDialog`
- 章详情用大号 textarea / `.sample-body`，保存走 PATCH（`useDirtyGuard`）
- 导出按钮打 `manuscript.md`

## 明确不做

- 一句话生成大纲、一键写完全书、流式出字
- 人物卡 / 世界观卡 / 多卷
- 改试写上限或复用 `samples` 表
- 抽 `loadUserKey`（继续按 sample 包内复制，避免顺手重构）

## 验证

- `go test ./internal/write/...`：brief 校验、target 夹取、prompt 含上一章摘要、缺 key 失败
- `web` 里 `npm run build`
- 本机：列 3 章 → 写第 1 章 → 改摘要 → 写第 2 章（确认 prompt 带上第 1 章摘要）→ 导出 md → 刷新后任务坞仍能跳到章节页
- 禁语回归：正文不得出现「模仿作者」一类句子
