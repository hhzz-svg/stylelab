# 章节工作台设计

日期：2026-08-19
状态：已确认
范围：章节详情页 `/p/:id/chapter/:chapterId` 的阅读与编辑体验

## 1. 背景与目标

写作链路已经能用：章程列表、整章生成、前情摘要、手改正文。章节页仍是一张长表单，写的时候看不到风格卡和上一章，读稿和改稿挤在一起。

这次只把章节页收成可扫描的编辑台。生成协议、字数区间、job 流程、章程列表页都不改。

成功标准：

1. 桌面上，作者可以同时看见正文、当前风格卡九维/约束、上一章摘要和文末。
2. 窄屏默认只看正文；风格卡和前情从抽屉打开，不跟正文抢高度。
3. 保存、写/重写、上一章/下一章、回章程都在粘性栏，键盘和触控都能完成。
4. 未保存修改切章前会被确认。没有上一章或下一章时对应按钮禁用。
5. 不新增后端接口，不改变 `PATCH /api/chapters/:id` 和 `POST /api/chapters/:id/write` 的契约。

## 2. 已确认决策

| 决策 | 选择 |
|---|---|
| 本轮范围 | 只重排章节页。不改生成协议，不做续写/段改写，不改章程列表。 |
| 桌面侧栏 | 常驻风格卡 + 前情。 |
| 窄屏 | 先正文，侧栏变抽屉。 |
| 本章设定 | 标题、概括、目标字数、补充说明、模型收到正文上方折叠区，默认只露出标题和字数。 |
| 数据 | 复用现有章节、章节列表、卡片接口。上一章正文按需再取一次，页面内缓存。 |

明确不做：

- 续写、按段改写、流式输出、任务取消
- 章节重排拖拽、对照修订、多人协作
- 新的章节上下文 API
- 章程列表大改

## 3. 布局

### 3.1 桌面（约 1024 以上）

两栏工作区，沿用卡片工作台的不透明面板、8px 卡片圆角、2.5rem 控件高度、金色焦点环。

- 左栏：本章设定（折叠）+ 正文编辑区 + 本章摘要。
- 右栏：风格卡情报、前情情报。
- 底栏：粘性操作。正文区最小宽度优先，情报栏大约 280–340px，使用 `minmax(0, 1fr)`，不横向溢出。

### 3.2 窄屏

默认只渲染左栏。顶栏或粘性栏提供「风格卡 / 前情」按钮，打开与牌库抽屉同类的视口抽屉。关闭抽屉后焦点回到正文。

1440×900、1024×768、390×844 都不得重叠或横向溢出。`prefers-reduced-motion` 下抽屉和折叠不做过渡动画。

### 3.3 本章设定

折叠摘要默认显示：`第 N 章 · 标题 · 当前字数 / 目标字数`。展开后编辑：

- 标题（≤40 字）
- 风格卡选择
- 模型（可选）
- 章概括（≤200 字）
- 目标字数（2000–3500，步进 100）
- 这一次补充（≤200 字，只作用于下一次生成）

这些字段的校验和提交形状与现有章节页相同。

### 3.4 正文与摘要

正文是主编辑面，显示实时字数。本章摘要单独一块，说明它会留给下一章当连续记忆。生成中正文只读，进度条仍用现有 `JobProgress`。

### 3.5 风格卡情报

有绑定卡时显示：名称、类型、版本、九维条、约束列表，以及「进入实验室」链接。九维条复用牌库检视器的呈现，不引入新的稀有度或战斗语言。

未绑定卡时显示空状态，并链到 `/p/:id/cards`。点「写这一章」仍按现有后端校验：「先选一张风格卡再写」。

### 3.6 前情情报

有上一章时显示：上一章标题、摘要、正文最后约 300 字（与后端 `prevTailRunes` 一致）。没有上一章时写明这是开篇。上一章加载失败时保留摘要（若列表里已有 `has_summary`），文末处给出重试，不挡住正文。

## 4. 数据流

打开 `/p/:projectId/chapter/:chapterId` 时并行请求：

1. `GET /api/chapters/:chapterId`
2. `GET /api/projects/:projectId/chapters`
3. `GET /api/projects/:projectId/cards`（设定区下拉仍只要 `CardSummary`）
4. 若本章有 `card_id`，`GET /api/cards/:cardId`（侧栏九维只在检视时拉全文）

上一章由章节列表按 `seq` 计算。若存在上一章，再 `GET /api/chapters/:prevId`，只使用 `summary` 和 `body` 的尾部 300 字。结果按章节 id 缓存在本页。切到相邻章时，只要缓存里有上一章或当前章，就不再重复拉全文。

保存：`PATCH /api/chapters/:id`，字段与现在相同。
写/重写：先按现有逻辑保存脏的设定字段，再 `POST /api/chapters/:id/write`。`autoNavigate` 保持关闭，成功后留在本章并刷新正文。

不新增、不修改后端路由或数据库 schema。

## 5. 交互

- 粘性栏：保存（无改动时禁用）、写这一章 / 重写这一章、上一章、下一章、回章程。
- 重写已有正文前，继续使用现有确认框。
- 切章时若有未保存修改，先确认；取消则留在本章。
- 没有上一章或下一章时，对应按钮禁用，不循环到目录两端。
- 生成中禁用写/重写；正文只读。设定区与摘要仍可改，保存按钮在有未保存修改时可用。
- 抽屉、折叠、按钮均可键盘聚焦；焦点环沿用共享样式。

## 6. 错误处理

| 状态 | 表现 |
|---|---|
| 本章加载失败 | 整页错误 + 重试，不渲染空编辑台 |
| 章节列表失败 | 仍显示本章；上一章/下一章禁用；前情显示加载失败和重试 |
| 风格卡失败 | 侧栏错误 + 重试；正文可继续手改和保存 |
| 上一章全文失败 | 摘要若已有则保留；文末显示重试 |
| 保存失败 | 粘性栏附近显示错误，不丢本地编辑 |
| 写章提交失败 | toast 或栏内错误；保持可再次提交 |
| 写章 job 失败 | `JobProgress` 显示 `job.error`；章节状态按后端变为 `failed` |

## 7. 视觉与无障碍

沿用 2026-08-19 卡片工作台视觉：不透明混合明暗面板，去掉 aurora / 厚重玻璃。卡片和情报块圆角不超过 8px。控件高度 2.5rem。可见 `:focus-visible`。所有工作流都有点击、键盘、触控路径。
