# 章节工作台安全与 UI 加固设计

日期：2026-08-19

状态：设计已确认，边界修订已确认

范围：章节详情页 `/p/:projectId/chapter/:chapterId` 的前端状态一致性、布局和交互

## 1. 业务结论

本轮采用“定点加固”，保留现有章节工作台和写作接口，只处理会导致误写、覆盖、重复提交或阻塞正文编辑的问题。不重构整个写作模块，不增加后端能力，也不扩展到其他页面。

完成后，作者应能可靠地确认“当前正在编辑哪一章、页面正在执行什么操作、现在能否安全保存或生成”，并在桌面、中等宽度和手机上直接进入正文。

## 2. 已确认范围

### 2.1 本轮完成

- 隔离切章时的过期请求，禁止旧章节内容落到新路由。
- 将当前章节加载与牌库、邻章、风格卡、前情加载解耦。
- 统一保存、提交生成、生成中和生成后刷新阶段，阻止冲突操作。
- 修正重写判断、一次性补充、模型草稿和离开提醒的语义。
- 将主要操作移到工作区顶部并保持可达。
- 消除折叠设定区大块空白、正文过窄、操作栏遮挡和 CSS 命名冲突。
- 在宽度不足时把情报栏改为可访问的模态抽屉。
- 完成三个目标视口和关键状态矩阵的浏览器验证。

### 2.2 明确不做

- 不修改 `PATCH /api/chapters/:id`、`POST /api/chapters/:id/write` 或数据库结构。
- 不实现服务端幂等键、活动任务查询、ETag、版本号或跨标签页冲突处理。
- 不改变提示词、生成上下文、前情范围、摘要规则或风格卡版本规则。
- 不增加续写、段落改写、流式输出、取消任务或章节重排。
- 不改造 `Write.tsx`、其他工作台或全局视觉系统。
- 不把全局 `BrowserRouter` 迁移为 Data Router；浏览器后退不做不可靠的页面内回跳拦截。
- 不包含公网部署。

## 3. 成功标准

1. 路由显示 B 章时，页面不可能继续编辑或提交 A 章数据。
2. 牌库或章节列表失败时，当前章节正文仍可加载、编辑和保存。
3. 保存和生成请求不能被双击重复提交；请求期间不会用响应静默覆盖新输入。
4. 已保存正文存在时，即使本地正文被清空，生成仍按“重写”处理并要求确认。
5. 未选择风格卡或章概括为空时，不发送写作请求，并把用户带到缺失字段。
6. 桌面首屏直接出现正文；1024px 和 390px 下正文不被情报栏压窄。
7. 情报抽屉顶部和关闭按钮始终在视口内，支持 `Esc`、焦点约束和关闭后焦点恢复。
8. 1440×900、1024×768、390×844 均无横向溢出、操作栏遮挡或 JobDock 冲突。

## 4. 方案选择

采用定点加固，而不是以下两个方向：

- 视觉优先：改动更快，但会保留跨章误写、重复生成和刷新覆盖风险。
- 完整重构：拆成新的状态 Hook 和多层组件边界会扩大脏工作树中的施工面，本轮没有必要。

实现应继续沿用 `Chapter.tsx` 作为页面编排层、`ChapterIntelPanel.tsx` 作为情报呈现层、`chapterContext.ts` 作为纯辅助逻辑。只有出现真实复用时才新增抽象。

## 5. 状态与数据流

### 5.1 页面身份

页面所有写操作以已加载章节 `ch.id` 为目标，不直接信任尚未完成加载的路由参数。只有同时满足以下条件时才开放保存和生成：

- `ch.id === chapterId`
- `ch.project_id === projectId`
- 当前没有新的路由加载正在替换该章节

章节页拥有的上一章、下一章、回章程和情报链接都先基于持久修改与临时生成草稿执行同一离开判断；用户取消时不得导航，也不得清空任何状态。用户确认离开后才提交路由变化。新的 `chapterId` 生效时立即清空旧章节和旧情报，进入不可编辑的加载态，同时清理上一章遗留的 `jobId`、操作阶段和一次性补充。

刷新和关闭页面继续由 `useDirtyGuard` 保护。当前普通 `BrowserRouter` 无法可靠拦截 SPA 浏览器后退；本轮把它记录为已知限制，不迁移全局路由，也不使用会闪屏或丢状态的 `popstate` 回跳技巧。

### 5.2 过期请求隔离

每轮路由加载持有递增的请求序号和目标章节 ID。章节、卡片和前情请求返回时必须核对序号及目标 ID；不匹配的结果直接忽略。

当前章节、卡片摘要列表和章节摘要列表可以并行请求，但分别处理结果：

- 当前章节失败：整页失败，可重试。
- 卡片列表失败：正文继续可用，设定区显示局部错误和重试。
- 章节列表失败：正文继续可用，上下章导航禁用，前情区显示局部错误和重试。

卡片详情和上一章全文只在对应 ID 已确认后请求。新请求开始时旧内容退出正常展示，加载、失败、空状态和正常内容必须互斥。

### 5.3 操作阶段

页面加载与写操作分开建模。写操作只使用以下阶段：

- `idle`：允许编辑。
- `saving`：正在保存持久字段。
- `submitting`：正在补保存设定并提交生成任务。
- `generating`：任务已受理或服务器章节状态为 `writing`。
- `refreshing`：任务成功，正在读取最新正文。

进入任一非空闲阶段后，保存和写作按钮立即禁用。保存、提交和刷新期间锁定所有编辑控件；生成期间锁定会与生成结果冲突的章节编辑控件，但仍允许安全离开页面。

写作点击处理在任何 `await` 之前进入 `submitting`，并在处理函数入口拒绝重复调用。页面重新打开后若章节状态为 `writing`，直接进入 `generating`，用现有章节读取接口轮询到终态；不增加活动任务接口。

任务成功时将 `JobProgress` 的自动跳转关闭，先进入 `refreshing`，只有最新章节成功应用后才回到 `idle`。刷新失败时保持编辑锁定，显示“生成完成，刷新失败”和重试，防止在旧正文上继续保存。

为区分真实任务失败与进度读取失败，`JobProgress` 只增加可选的轮询错误回调。章节页传入该回调时，`onStatus` 仅从实际任务快照转发；未传入时保留现有调用方的状态回调和自动跳转行为，不修改 `useJobPoll` 或其他页面。

### 5.4 持久修改与临时生成草稿

区分两类修改：

- 持久修改：标题、章概括、正文、摘要、风格卡、目标字数。
- 临时生成草稿：本次模型和一次性补充。

保存按钮只由持久修改控制。离开提醒由两类修改共同控制，并明确说明临时生成设置也会丢失。

一次性补充只在写作任务成功受理后清空；提交失败时保留。切换章节前若尚未消费，必须进入离开确认；确认离开后清空。模型字段标注为“本次生成模型（留空使用默认）”，不假装会随普通保存持久化。

### 5.5 写作前置检查与重写

写作前镜像现有服务端规则，只检查：

- 已选择风格卡。
- 章概括去空白后非空。

缺失时不发送请求，自动展开本章设定并聚焦第一个缺失字段。不得自行增加新的生成必填条件。

只要服务器已保存正文或本地正文任一非空，就按重写处理。重写确认发生在补保存和写作请求之前。

## 6. 页面布局

### 6.1 操作与导航

工作区顶部新增粘性命令栏，显示当前操作状态，并承载：

- 情报入口（情报栏隐藏时显示）
- 保存
- 写这一章 / 重写这一章

上一章、回章程、下一章移到标题区的紧凑导航，避免手机命令栏堆入六个按钮。命令栏位于页面内容顶部，不使用会与 JobDock 冲突的底部固定定位。

### 6.2 正文与设定

本章设定继续使用折叠区，但增加生成准备摘要，例如“风格卡已选 · 章概括已填 · 目标 2600”。章节专用样式覆盖通用 `.work-zone` 的 410px 最小高度，折叠时只占摘要本身的高度。

章节主栏改用独立类名，避免与章程列表链接的 `.chapter-main` 冲突。正文编辑区获得主要纵向空间，页面初次进入时无需滚过空面板才能看到正文。

### 6.3 响应式规则

- 视口宽度不小于 1180px：正文和情报两栏常驻。
- 视口宽度小于 1180px：正文单栏，情报通过命令栏按钮打开。
- 视口宽度不大于 900px：沿用全局移动导航，命令栏保持在移动顶栏下方。

1024px 主动使用单栏是已确认的取舍：牺牲情报常驻，换取可用的正文宽度。

### 6.4 情报呈现

桌面情报栏继续显示风格卡和前情，但取消章节情报块继承的通用最小高度。九维从九条纵向进度条改为紧凑的 3×3 信息格，保留维度名称和数值；约束、上一章摘要和文末仍直接可读。

这次只重排已有信息，不新增算法、评分、推荐或风格解释。

## 7. 情报抽屉

窄屏情报不复用当前受页面动画变换影响的固定侧栏。它通过 portal 挂到 `document.body`，使用原生模态 `dialog`：

- `showModal()` 打开并提供模态与焦点约束。
- 固定抽屉标题和关闭按钮，内容区域独立滚动。
- `Esc`、关闭按钮和点击遮罩均可关闭。
- 打开时聚焦关闭按钮或标题后的首个可操作元素。
- 关闭后焦点回到“风格卡 / 前情”触发按钮。
- 从抽屉内触发需要离开确认的链接时，先暂时关闭原生模态，再调用全局确认框；用户取消后重新打开抽屉并恢复焦点，确认后直接导航。这样避免 `showModal()` 使抽屉外确认宿主不可交互。
- `prefers-reduced-motion` 下不添加过渡。

抽屉专用于章节情报，不顺带重构牌库抽屉。

## 8. 错误与降级

| 场景 | 页面行为 |
|---|---|
| 当前章节失败 | 整页错误与重试，不显示旧编辑器 |
| 卡片列表失败 | 正文可用；卡片选择局部错误与重试 |
| 章节列表失败 | 正文可用；邻章导航禁用，前情局部错误与重试 |
| 风格卡详情失败 | 情报区错误与重试，不影响正文 |
| 上一章全文失败 | 显示读取失败与重试，不同时显示“没有摘要” |
| 保存失败 | 回到空闲，保留全部本地输入，栏内错误并辅以 toast |
| 写作提交失败 | 回到空闲，保留一次性补充和本地输入 |
| 任务失败 | 解除生成锁定，保留本地内容并显示任务错误 |
| 生成后刷新失败 | 保持编辑锁定，明确生成已完成并提供刷新重试 |
| 轮询暂时失败 | 保持写作禁用，允许重试状态或安全离开，避免重复生成 |

### 9.1 工程验证

- 在 `web/` 执行 `npx.cmd tsc --noEmit`。
- 在仓库根目录执行 `go test ./internal/write ./internal/httpapi -count=1`。
- 对本轮文件执行 scoped `git diff --check`，避免批量换行或格式变化。

不为本轮引入新的前端测试框架。

### 9.2 浏览器状态矩阵

使用 Playwright CLI 和浏览器内模拟 API 数据检查：

- 延迟加载 A 章后立即切到 B 章，最终只能显示和提交 B 章。
- 卡片列表或章节列表失败时，B 章正文仍可编辑和保存。
- 连续点击保存或生成只发出一个请求。
- 服务器已有正文、本地清空后仍显示“重写”并要求确认。
- 缺少风格卡或章概括时，设定区展开并聚焦缺失字段。
- 一次性补充在提交失败后保留、任务受理后清空、切章前触发提醒。
- 任务成功后停留本章，刷新完成前编辑保持锁定。
- 1440×900、1024×768、390×844 均检查首屏正文、命令栏、横向溢出和遮挡。
- 390×844 检查抽屉顶部、内部滚动、`Esc`、焦点约束与焦点恢复。

### 9.3 完成证据

只有类型检查、Go 回归、状态矩阵和三个视口检查都具备可信证据，才能在 `progress.md` 中记录为完成。无法执行的验证必须明确记录为缺口，不能写成已可用。
